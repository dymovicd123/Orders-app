# Склад: подготовка к внутренним штрихкодам (без включения сканирования)

Статус: **контракт будущего внедрения**. W12 не выдаёт новые коды, не добавляет миграций,
не требует принтера, не меняет остатки или подтверждение операций.

## Идентичность

- Штрихкод идентифицирует **точный активный catalog variant**, не название модели и не
  складскую запись конкретной точки. Размер/цвет/материал/длина/пол важны при создании
  варианта, но после назначения штрихкод связывается с постоянным canonical variant ID.
- Один вариант имеет одинаковый код на каждой физической вещи данного варианта;
  количество определяется повторными сканами. Это не серийный учёт экземпляров.
- Наличие и резервы всегда считаются отдельно по **warehouse/boutique**.
  В этикетку не записывают склад или количество.
- Нужна уникальная таблица связей barcode → active canonical variant ID,
  с проверкой уникальности, отсутствия конфликта с другим активным вариантом,
  защищённой сменой кода, запретом невидимого восстановления retired-вариантов и
  аудитом переназначений. Для слияний variants — явное правило миграции алиасов кода.
- Существующий variantId можно показывать для диагностики, но **не** трактовать
  его как готовый сканируемый штрихкод или публичный GTIN/EAN.

## Сканирование

1. Сканер USB/Bluetooth как keyboard wedge или камера вводит строку в поле
   выбранной операции. Решатель возвращает только точный active variant ID.
2. Неизвестный/неоднозначный/отключённый код требует ручного выбора и исправления
   каталога; никаких автоматических приходов или безусловного создания SKU.
3. Приход: повторный скан добавляет +1 в черновик прихода.
   Списание и перемещение: повторный скан добавляет 1 к черновику операции;
   направление склада/бутика выбирается человеком заранее.
   Ревизия: сканы формируют **фактический подсчёт**, а не прибавку к остатку.
   Корректировка: скан помогает выбрать вариант, пользователь указывает точный факт.
4. Результат всегда проходит существующий W6/W9 preview → confirm →
   серверную идемпотентную inventory-movement transaction. Скан сам не сохраняет данные.
5. Отправка заказа отдельно: скан может проверить комплектовку и выбранный variant ID,
   но не должен повторно списывать/резервировать проданный товар.

## Печать и организация

- Если цех прислал немаркированные вещи, приёмщик сначала выбирает точные варианты,
  затем печатает нужное число одинаковых этикеток на вариант.
- Внутренние этикетки должны содержать читабельные название, размер, цвет и код;
  печать PDF пригодна для пилотного запуска. Code 128 может кодировать внутренние
  идентификаторы без регистрации международных GTIN.
- Разрешить ручной выбор товара всегда; отсутствие этикетки не блокирует склад.
- Начальный пилот: 2–3 модели и несколько десятков вещей, сравнение времени
  приёмки, перемещения и ревизии и частоты ошибок.

## Проверки перед релизом сканирования

- Скан одинакового SKU несколько раз и нескольких разных SKU.
- Переключение склад ↔ бутик в середине черновика; запрет переноса сканов
  одной точки в другую без явного действия.
- Повторная отправка requestId, сетевые ошибки, конфликт ожидаемого остатка.
- Нулевой остаток, retired-вариант, алиас после объединения, дубли кода.
- Заказ, резерв, возврат, обмен, выдача, отмена — без двойных списаний.
- Запрет создания активного SKU из неизвестного кода без подтверждения человека.
