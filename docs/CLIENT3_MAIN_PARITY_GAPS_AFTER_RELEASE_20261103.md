## Подтверждённые расхождения по исходному коду (не включены в завершённый выпуск)

### Высокий приоритет для решения о переносе
1. **История клиентов — отдельный раздел Main отсутствует.** Main: `src/features/sections/ClientsSection.tsx` — список клиентов, поиск, повторные клиенты, клиенты с долгом, карточка и история заказов. Client3: `src/WatchClient3App.tsx` не содержит раздела `clients`; наличие имени/телефона в заказе не заменяет CRM-историю. Нужен серверный запрос с ограничением бренда/ролей, исключающий смешение клиентов других брендов (с возможным общим контактом как бизнес-правило — уточняется).
2. **Общая история возвратов/обменов отсутствует как самостоятельная рабочая лента.** Main: `OrderReturnsSection.tsx`, `OrderExchangeSection.tsx` — фильтруемые истории, старые/новые позиции, действия, статус приёмки. Client3: `WatchReturnsPanel.tsx` — только очередь ожидающей приёмки; `WatchOrdersPanel.tsx` — формы действий из конкретного заказа. Финансы показывают денежные события, но не все безденежные обмены и движения товаров. Нужна брендовая история с поиском и деталями и связью с приёмкой.
3. **Складская статистика не перенесена отдельной вкладкой.** Main: `InventorySection.tsx` содержит `statistics` с анализом популярных товаров/характеристик, продаж и средних цен; Client3: в складской навигации `WatchClient3App.tsx` нет `statistics`. Отчёт «Товары» частично заменяет продажи, но не полный складской анализ по вариантам часов (механизм, материал браслета, циферблат, ремешок).
4. **Финансовый журнал пока ограничен 300 записями на выбранный период.** `worker/domains/client3-watch-analytics.ts` содержит `LIMIT 300` для `events`, а `WatchFinancePanel.tsx` предупреждает об ограничении, но не позволяет загружать продолжение. Main использует поисковую/фильтруемую подгрузку с пагинацией `moneyHistoryHasMore`. Суммы и дневные агрегаты считаются сервером по полному периоду; проблема именно в подробном журнале, сверке дат и истории долгов/возвратов.
5. **Ревизия не полностью равна Main по вспомогательным функциям.** `renderInventoryStocktakePanel.tsx` Main предлагает рекомендации по давности/движениям/прошлым расхождениям, печатный лист, продвинутые действия по «найденным вещам», подробный блок последствий нехватки. `WatchWarehouseMain.tsx` рекомендует только по резервам, а `WatchPersistentRevision.tsx` не имеет печатного листа и того же объёма пост-ревизионной диагностики. Базовая надёжная ревизия уже есть; не подменять её очередной корректировкой.

### Средний приоритет / полировка
6. **Складская история проще Main.** `WatchWarehouseStage5.tsx` содержит чтение операций по точке и «Показать ещё», но нет Main-поиска по событию/товару и подробной карточки ревизии (`InventorySection.tsx`).
7. **Команда — не полная функциональная копия Main.** В Client3 есть основной состав, табель, планы, зарплата и агрегированная активность, но не все функции детальной истории действий и Word/PDF-экспорта раздела `TeamSection.tsx` Main. Проверить полезность именно для часов; не копировать нерелевантные поля.
8. **Отчёты близки, но не полностью идентичны.** Client3 имеет 7 категорий и Word/TSV/печать; в Main `FinanceReportContentRenderer.tsx` есть расширенные ежедневные разбивки и контрольные таблицы по оплатам, товарам, менеджерам и возвратам. В Client3 часть детализаций есть, но не весь объём. Отдельно проверить экспорт полного периода, если число записей станет большим.
9. **Реальная пользовательская приёмка.** Проверить в Chrome/Windows и на мобильном: администратор/менеджер/логист, выбор брендов, справочники кириллицей, отправку/обмен/приёмку, сохранённую ревизию, денежные журналы, стартовую и рабочую общую кассу. Не менять фактические остатки без контролируемой тестовой процедуры.

- База: создание варианта никогда не добавляет физический остаток; он появляется лишь после отдельного прихода.
