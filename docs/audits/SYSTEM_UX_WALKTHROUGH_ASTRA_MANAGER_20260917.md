- Проверен только live Branch2: https://orders-app-branch2.orders-clothes.workers.dev, UI «Система заказов 2», «Рабочий режим», «Роль: Менеджер».

### A. Repeated root causes

1. **Разные входы не разделяют единый процесс.** Отложенная нехватка, очередь определения товара и resolver заказа требуют от сотрудника знания внутренней карты системы (M-01, M-02).
2. **Не различены предположение, локальный выбор и сохранённый факт.** Галочки, пустой размер и готовый итог прихода дают разные смыслы без устойчивого визуального различия (M-03, M-04, M-06).
3. **Объяснение заменяет контекстное состояние.** Неактуальное поле Цеха и поздняя ошибка возврата заставляют читать и интерпретировать вместо очевидного следующего шага (M-05, M-07).
4. **Текст отстаёт от поведения и структуры.** Указание на «Внимание» и конфликт дат отчёта нельзя исправить добавлением ещё одного поясняющего абзаца (M-01, M-08).

### B. Things that were actually clear

- M1: основные названия «Заказы», «Клиенты», «Цех», «Склад» соответствуют ожидаемым задачам. Общая навигация: **No material issue found**, кроме описанных точечных расхождений; все 11 разделов подробно не обходились.
- Создание: блоки клиент → товары → оплаты → проверка; отсутствие менеджера имеет видимую причину disabled-кнопки. Сохранение возвращает к таблице, данные и долг 100 совпали.
- Таблица: «Не оплачено / Не отправлен», получено 0 и долг 100 понятны. Возврат/обмен открываются непосредственно из нужной строки.
- Resolver D: один вопрос, быстрые варианты пола, затем отдельная финальная кнопка. Текст предупреждает, что после уточнения продолжится проверка отправки. Само продолжение отправки не тестировалось.
- Остатки: «На месте / В заказах / Свободно» разделены; отрицательное свободное количество не скрыто. «1 в заказах → Открыть заказ» привело в заказы с поиском по правильному ID.
- «Проверка»: выбор нескольких товаров или полной точки, причина неактивного старта «Выберите хотя бы один товар» — понятны. Полная ревизия не запускалась.
- Цех: одна TEST-позиция, явные «Редактировать заказ» и «Готово»; в заказах написано, что отправка всего заказа возможна после готовности Цеха. В просмотренном исходном состоянии противоречия не найдено.
- Возврат/обмен различают старую вещь, место физического поступления и деньги; вариант «Ещё не пришла» не притворяется уже принятым остатком.
- Финансы: за период продажи 107 / 6 заказов / поступило 0; по дням 17.09 — продажи 100, поступило 0, что соответствует созданному заказу. **No material issue found** в этой ограниченной визуальной сверке; ненулевые расчёты не тестировались.

### D. Admin-pass targets

- Контекстный переход из «Нужно уточнить → Товар» к разбору уже известного товара: почему здесь требуется администратор, когда заказ даёт менеджеру точное подтверждение.
- Неизвестный товар TEST-G: как администратор получает исходный контекст и завершает три строки, не заставляя менеджера повторять работу.
- Исключение неизвестного пола TEST-D: насколько понятно отделено от обычного выбора пола и сохраняет ли контекст передачи.
- Проверки перед сохранением прихода с пустыми цветом/размером и подразумеваемым количеством: проверить на изолированных disposable-позициях, не реальных остатках.
- Допустимый путь для неоплаченного/неотправленного заказа, из которого доступен возврат: уточнить существующее правило без придумывания новой финансовой семантики.
