# Stage04-D2 — заметная очередь незаполненной себестоимости (Branch2, 2026-10-11)

## Проблема
При готовности товара без подтверждённой себестоимости цех продолжает работу, но долг перед цехом не увеличивается. Ранее администратор должен был сам найти подраздел «Без себестоимости» внутри «Расчёты с Цехом», где запись выглядела как пассивная «Нужна проверка». Такую работу легко пропустить.

## Исправленный сценарий
- На **всём экране «Цех»** (обычные заказы, Kaspi и сами расчёты) администратору показывается стойкое янтарное предупреждение «Не определена себестоимость: N позиций». Есть крупная кнопка «Разобрать позиции».
- На вкладке «Расчёты с Цехом» — заметный счётчик «N без цены». Из предупреждения открывается сразу очередь «Без себестоимости», даже если оно нажато повторно.
- Количество всех активных непогашенных missing-cost событий считается в SQL (не только первая страница из 50). Обновляется при входе в цех, после изменения статуса готовности, при возвращении вкладки в фокус, каждые 60 секунд пока экран открыт, и после подтверждения цены.
- Для каждой строки сервер возвращает **состояние**: `missing_cost` (SKU однозначен, цены нет); `ready` (цена уже сохранена, начисление ожидает подтверждения); `needs_match` (нет достоверной связи с вариантом, недостаточно просто изменить цену).
- **«Указать себестоимость»** открывает нужный товар в каталоге только когда SKU подтверждён; иначе «Проверить товар» открывает поиск по названию без ложного автоматического назначения варианта.
- После сохранения администратор возвращается в Цех, нажимает «Обновить» и «Подтвердить начисление». Не происходит автозаписи долга из-за самого редактирования каталога.

## Доступ и учёт
Цены изменяет только администратор через прежний защищённый Catalog API. Предупреждение, финансовая очередь и подтверждение доступны только администратору. Неизвестная себестоимость остаётся NULL; выплаты и начисления не блокируют обычную работу цеха. Старые завершённые финансовые события не пересчитываются, текущая Branch2 тестовая D1 и production не модифицируются этой доработкой.

## QA
Stage04-D SQLite regression дополнен проверками полного счётчика, различения отсутствующей цены/неоднозначного SKU, каталожного product ID и присутствия постоянной предупреждающей плашки, связанной с переключателем. Прогон исторических тестов на замороженных файлах сохранён; после него перепроверяется новый текущий экран. Cloudflare live UI smoke требует новых надписей. Только `branch2`, `main` без изменений.
