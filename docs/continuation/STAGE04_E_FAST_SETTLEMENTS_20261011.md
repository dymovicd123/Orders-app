# Stage04-E — быстрые расчёты с Цехом без кассовой интеграции (Branch2, 2026-10-11)

## Решение
По запросу пользователя радикально сокращён ежедневный сценарий. Цех обычно получает оплату в день готовности, долг может переноситься. Авансы не допускаются. Способ оплаты **пока необязателен**, потому что расчёты с цехом сейчас изолированы от кассы и отчётов; вопрос реального движения денег клиент уточнит отдельно.

## Интерфейс
- На первом экране: общий подтверждённый долг крупно, отдельно готовая работа сегодня и выплачено сегодня.
- Две быстрые команды: «Выплатили полностью» и «Выплатили часть». Обе открывают короткую панель подтверждения; у полной выплаты сумма **заморожена в момент открытия**, а сервер ещё раз сравнивает её с актуальным долгом в атомарном SQL INSERT.
- Свободного обязательного поля способа больше нет. «Дополнительно (необязательно)» раскрывает варианты «Не указывать», «Наличные», «Kaspi Pay» и комментарий. Неизвестный способ хранится как NULL, не считается наличными и не списывает средства в каком-либо журнале кассы.
- Кнопка подтверждения явная, ошибки дублирования не создают дополнительную выплату: UUID idempotency, невозможность переплаты, append-only история/отмена и доступ только администратора сохраняются.
- В начале загружается только краткая сводка и последние 6 событий через admin-only GET `/api/workshop/settlements/summary`, **без** тяжёлой таблицы за 30/90 дней и списка цен; родительский «Цех» уже продолжает мониторить нерешённые цены.
- Подробные разделы «Начисления», «История операций», «По дням» и «Без себестоимости» обращаются к API только при открытии. Начисления имеют серверную фильтрацию `scope=work`, чтобы выплаты не скрывали готовые изделия при постраничной загрузке.
- Фильтры дат доступны только на подробных экранах. Три основные вкладки «Цех» помещаются в одну строку на десктопе, с адаптацией к телефону. Постоянная янтарная плашка нерешённых себестоимостей не затронута.
- «Сегодня выполнено» теперь включает только события готовности текущего дня; подтверждение цены для готового ранее изделия показывается отдельно как «уточнена стоимость ранее готовых изделий», даже если это текущая бухгалтерская дата. Дневная таблица отделяет готовую работу и поздние подтверждения себестоимости.
- Отдельно показываются завершения по конкретным товарам, их количестве и стоимости единицы. Заказ/остатки не мутируются при открытии истории.

## Финансовые ограничения
- **Нет** интеграции с кассой, финансовыми отчётами, входящими оплатами клиентов или банковскими операциями. Нельзя делать вывод о реальном движении наличных на основе платежей этого раздела.
- Тестовая `branch2` содержит тестовые начисления. Никаких миграций, ретроспективных списаний, изменений цен/склада, production или main.
- Вопрос кассы и источника денег должен быть решён с клиентом до боевого переноса. Если источник обязателен для аудита реальных расходов, его можно требовать только при согласованном кассовом действии, а не в нынешнем изолированном тестовом интерфейсе.

## QA
- Регрессия in-memory SQLite: неизвестный метод NULL, повторы и конфликт того же UUID, запрет переплаты, возврат выплаты, корректное разделение завершённой работы и поздней стоимости, серверная фильтрация начислений, отсутствие тяжёлого ledger-query при открытии сводки.
- Stage04-C/D/B3 сохранены и прогоняются вместе с прежним историческим baseline через строгие SHA-pinned gates. Обязательная пересборка текущего фронтенда после frozen tests. Проверка живого Cloudflare lazy-chunk ждёт новые UI маркеры.
- Ручной визуальный QA и реальные кассовые тесты отдельно; при наличии браузера Work имеет смысл провести их до production.
