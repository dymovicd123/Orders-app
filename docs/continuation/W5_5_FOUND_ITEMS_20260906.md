# W5.5 — найденные и непонятные вещи — 2026-09-06

## Цель
Не терять физически найденную вещь во время проверки и одновременно не создавать мусорные значения каталога только ради завершения ревизии.

## Поведение
- Если все характеристики уже известны системе, найденная позиция добавляется в текущую проверку обычным безопасным путём.
- Если хотя бы одного значения нет в каноническом справочнике, ревизия не создаёт новый цвет/размер/материал/длину автоматически. Вместо этого создаётся изолированный физический факт без `variant_id` и позиция остаётся в текущем листе для ввода фактического количества.
- После завершения проверки такая вещь остаётся физически учтённой, но не участвует в обычных вариантах, перемещениях и выборе для заказов до определения точной идентичности.
- `Нужно уточнить → Товар` показывает найденную вещь заметной карточкой и прямо объясняет, почему она пока не видна среди обычных вариантов.
- Если точный вариант уже появился, менеджер может безопасно связать найденную вещь с ним. Общая физическая сумма при этом не увеличивается повторно.
- Если точного варианта ещё нет, требуется администратор: он исправляет/создаёт master-data в `Товары`, после чего найденную вещь можно связать с точным вариантом.
- Если ревизия завершается с такими позициями, интерфейс сразу переводит пользователя в `Нужно уточнить`, чтобы проблема не могла пройти незамеченной. После перезагрузки она остаётся в счётчике до решения.

## Права
Менеджер может проводить ревизию, фиксировать найденную вещь и связывать её с уже существующим точным вариантом. Создание новых канонических значений по-прежнему admin-only.

## Надёжность
- Неизвестная вещь хранится в существующем `inventory_stock` как строка без `variant_id`; новая таблица и миграция не нужны.
- Разрешение в существующий вариант retry-safe: исходная неопределённая строка должна ещё содержать исходное количество, иначе повторный запрос не добавляет его второй раз.
- Отмена активной проверки снимает активный marker с нулевых найденных placeholders.
- Успешное завершение ревизии не превращается в ошибку только из-за сбоя последующего refresh.
